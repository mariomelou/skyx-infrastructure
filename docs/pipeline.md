# IaC pipeline

The infrastructure pipeline is separate from the frontend and backend image pipelines. The backend workflow continues to own its ECS rollout and migration command; this pipeline must not duplicate either operation.

## Proposed workflow

- Pull requests: install with the lockfile, type-check, synthesize, and produce a reviewed `cdk diff --method template` using a read-only preview role. Fork pull requests run synthesis without AWS credentials.
- Main branch: repeat validation and publish the synthesized CloudFormation artifact.
- Manual production run: the `workflow_dispatch` input `deploy` defaults to `false`; the manual inputs can synthesize/diff the opt-in ECR, `SkyxObservability`, `SkyxEcsScaling`, `SkyxWaf`, or import-oriented `SkyxLogRetention` component. Observability requires an explicit same-account SNS topic ARN and approved thresholds; ECS scaling requires explicit per-service capacity and CPU targets; WAF requires explicit observation-only `count` mode; log retention requires an explicit accepted retention value. All hardening paths are validation-only for now. Only an explicit `true` for the reference-only path on `main`, with a protected GitHub environment and approved deployment role, can reach `cdk deploy --require-approval broad` after the change set is reviewed. ECR execution remains deliberately outside the generic deploy job until its import operator path is separately approved.
- Import work: never run automatically. The manual `import` input is disabled unless the repository administrator enables `AWS_IAC_IMPORT_ENABLED`; when enabled, the `production` environment reviewer and exact change-set ARN checks gate the one-resource ECR import, followed by post-import resource and diff verification. Adoption and hardening components cannot run together.

The workflow in `.github/workflows/iac.yml` is rooted at this repository, requires both OIDC role values instead of falling back to ambient credentials, verifies that both sessions resolve to AWS account `129346407469`, restricts deployment dispatches to `main`, and expects `AWS_IAC_PREVIEW_ROLE_ARN` and `AWS_IAC_DEPLOY_ROLE_ARN` to be configured. The preview role is created with a read-only policy, the preview variable is configured, and runs `34720445280` (reference-only), `34721825546` (manual ECR synth/diff), `34722446666` (guarded workflow with import/deploy skipped), `34723414012` (observability synth/authenticated diff with import/deploy skipped), `34723695223` (ECS scaling synth/authenticated diff with import/deploy skipped), `34723892039` (WAF synth/authenticated diff with import/deploy skipped), `34724135711` (log-retention synth/authenticated diff with import/deploy skipped), `34724652329` (main push with all safety gates and component paths), and `34724795811` (main push after the protected-gate handoff verifier) passed; the deploy role is created with the ECR-scoped policy, but the protected production environment and environment secret remain unconfigured. The role boundary is documented in [ci-iam-design-2026-09-12.md](ci-iam-design-2026-09-12.md) and [deploy-role-scope-2026-09-12.md](deploy-role-scope-2026-09-12.md).
